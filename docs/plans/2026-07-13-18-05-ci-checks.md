# ci checks

- Date: 2026-07-13 18:05
- Branch: ci-checks

## Problem / Context

No CI existed (`.github/workflows/` was absent), so a PR could merge broken TS,
lint errors, or unformatted code. `.prettierrc` was configured earlier but no
reformat pass had ever run, so the scaffold was not actually prettier-clean.

## Plan

Add a GitHub Actions workflow that guards every PR (and pushes to main) with:
prettier check, eslint, `tsc --noEmit`, and a production `next build`. Add the
missing npm scripts, a `.prettierignore` that excludes hand-written prose docs
(so Prettier never reflows markdown), and run one format pass so the repo passes
its own check on day one.

## Increments (test-first)

Verification is the CI suite itself, run locally before pushing.

1. impl: add `typecheck`, `format`, `format:check` scripts -> verify each runs.
2. impl: add `.prettierignore` (ignore build output, lockfile, public, `*.md`,
   `.worktrees`) -> verify `prettier --check .` scopes to code only.
3. impl: `npm run format` to normalise the scaffold -> verify `format:check` green.
4. impl: add `.github/workflows/ci.yml` (checkout, setup-node from `.nvmrc`,
   `npm ci`, format:check, lint, typecheck, build) -> verify all four steps pass
   locally (they do: prettier/eslint/tsc/build all green).

## Notes

- `*.md` is intentionally prettier-ignored: the docs/case-studies/briefs are
  hand-formatted prose (em-dash-free, hand-wrapped) and must stay under human
  control.
- `data/portfolio.ts` on the `portfolio-data` branch was prettier-formatted
  separately so that PR is also green once this CI merges.
- Node version comes from `.nvmrc` (24) for Vercel parity.
