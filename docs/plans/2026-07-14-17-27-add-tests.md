## Problem / Context

The repo has **zero automated tests** — CI is a static gate only (`prettier
--check` -> `eslint` -> `tsc --noEmit` -> `next build`, in `.github/workflows/ci.yml`).
It catches compile/lint/format/build errors but verifies **no runtime behaviour**.
Recently a lot of regression-prone **client logic** was added (command palette,
collapsibles, TOC scroll-spy) and it's been verified only by manual screenshotting
— a matcher looseness bug (`/ttop` matched `/testimonials`) shipped and was caught
by the user, not a test. This work adds **Tier 1: Vitest + Testing Library** to
guard that logic, and wires it into CI.

Scope is Tier 1 only. A Playwright smoke e2e (Tier 2) is explicitly OUT of scope
for this PR — mention it as a follow-up if you like, don't build it.

## The tests to write (each its own commit)

Files under test all live in `components/` and `data/`. Read each component first.

1. **Palette matching** — `components/command-palette.tsx` uses `fuzzysort` over
   `{ keys: ["key", "label"] }`. The command list is defined inside the component
   (in a `useMemo`), so either (a) render `<PaletteProvider>` + `<HeroPrompt>`,
   open it, type, and assert the visible `role="option"` rows, or (b) if you
   refactor the command list / filter into an exported pure helper, unit-test that
   directly (cleaner — consider a small refactor to export a `filterCommands(query,
   commands)` fn). Assert: `/ttop` -> no matches; `/top` -> exactly `/top`;
   `test` -> `/testimonials`; `toggle` -> `/theme` (label match); empty -> all.
2. **Palette keyboard + a11y** — render, open via the `HeroPrompt` button (role
   button, `aria-label="Open command palette"`). Assert: input is focused; `↓`
   moves `aria-selected`/`aria-activedescendant`; `Enter` runs the highlighted
   command (spy on `next/navigation` `useRouter().push` — mock the module);
   `Escape` closes (dialog gone) and focus returns to the trigger. Mock
   `next/navigation`, `next-themes`, and `matchMedia`.
3. **Collapse a11y** — `components/collapse.tsx`. Render `<Collapse open={false}>`
   -> the panel wrapper has `inert`; `open={true}` -> no `inert`. And the
   grid class flips `grid-rows-[0fr]` <-> `grid-rows-[1fr]`.
4. **AboutMore reveal** — `components/landing/about-more.tsx`. Render it, dispatch
   `window.dispatchEvent(new CustomEvent("about:reveal", { detail: "skills" }))`,
   assert it opens (the toggle now reads "Show less" / `aria-expanded=true`) and
   `scrollIntoView` was called. Also assert a non-managed id (e.g. "nope") does
   NOT open it.
5. **Data invariants** — `data/portfolio.ts`. Pure, no DOM. Assert: project
   `slug`s are unique; every `caseStudy.testimonialId` resolves to a real
   `testimonials[].id`; every `featured` project either has a `caseStudy` or is
   intentionally card-only (encode the current intent — 4 featured have
   caseStudy); `generateStaticParams`-eligible = projects with `caseStudy`. These
   catch typo'd slugs/ids that `tsc` can't.

Keep tests behaviour-focused, not implementation-coupled. Prefer Testing Library
queries by role/text over test-ids. Where a component's logic is hard to reach
through the DOM, a SMALL refactor to export a pure function is preferred over
brittle DOM spelunking — but don't over-refactor.
