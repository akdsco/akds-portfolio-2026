# strict eslint

- Date: 2026-07-15 18:08
- Branch: strict-eslint

## Problem / Context

ESLint already existed (flat config) and already ran in CI (`verify` job:
format → lint → typecheck → test → build). But the config was thin — just
`eslint-config-next` core-web-vitals + typescript + prettier — with **no
type-aware rules**. So whole classes of bug (floating promises, misused
promises, `any` leaks, unnecessary conditions) went uncaught.

Owner asked: make the linter strict and fix every resulting error/warning.
(Chosen scope: strengthen ESLint. Not adding Stylelint — separate decision.)

## Plan

1. Add `typescript-eslint` as an explicit devDep.
2. Layer `strictTypeChecked` + `stylisticTypeChecked` onto the existing config,
   type-aware via `parserOptions.projectService`.
3. Disable type-checked rules on plain-JS config files (`*.mjs` etc.) — no type
   info there — and relax two test-only idioms.
4. Relax exactly one strict default that only creates noise:
   `restrict-template-expressions` → `allowNumber: true` (numbers-in-strings are
   safe). Everything else stays at full strictness.
5. Fix all 45 violations (41 via `--fix`, 4 empty-function bodies by hand).
6. Make warnings blocking: `lint` script runs `--max-warnings=0`.

## Increments (test-first)

1. test: `eslint.config.test.ts` asserts the marquee type-aware rules resolve to
   `error` on a `.tsx` source file, that `restrict-template-expressions` carries
   `allowNumber: true`, and that type-checked rules are **off** for `.mjs`
   config files (red against the old thin config) → impl: strict config + dep +
   fix all 45 violations (green: lint + typecheck + 28 tests all pass).
2. test: (covered by CI) → impl: `--max-warnings=0` on the `lint` script so a
   warning fails the build too; document the strict linter in CLAUDE.md.

## Notes

- `no-confusing-void-expression` (21 hits) kept strict — `--fix` wraps idiomatic
  `() => setX(v)` handlers in braces. Faithful to "strict"; zero manual effort.
- `consistent-type-definitions` converted 12 object-literal `type` aliases to
  `interface` (auto-fix, semantically equivalent).
- Verified: `npm run lint`, `npm run typecheck`, `npm run test` (28 tests) all
  green in the worktree.
