# sameas links

- Date: 2026-07-22 11:53
- Branch: sameas-links

## Problem / Context

The `Person`/`sameAs` JSON-LD emits all four `profile.socials`
(LinkedIn, GitHub, Stack Overflow, Pluralsight). The owner wants only the two
surfaced public-identity profiles — **GitHub + LinkedIn** — in `sameAs`; Stack
Overflow and Pluralsight are reference-only data, not identity.

The nav already encodes exactly this set (`site-nav.tsx`:
`profile.socials.filter(s => s.label === "GitHub" || "LinkedIn")`). Duplicating
that predicate in the JSON-LD builder is the drift-prone smell — one place could
change and the two disagree.

## Plan

Extract a single source of truth and use it in both places:

- `data/portfolio.ts` — export `publicSocials`, the GitHub + LinkedIn subset of
  `profile.socials` (the surfaced public-identity profiles).
- `components/site-nav.tsx` — source `navSocials` from `publicSocials` (behaviour
  unchanged; it already filtered to the same two).
- `lib/structured-data.ts` — `sameAs: publicSocials.map(s => s.url)` instead of
  all of `profile.socials`.

## Increments (test-first)
