# company links

- Date: 2026-07-16 16:07
- Branch: company-links

## Problem / Context

Company names render as dead text in three places (`landing/experience.tsx`,
`projects/project-card.tsx`, `case-study/meta-card.tsx`). Two of the entities are
still operational and worth linking; the rest are sold or wound down.

Verified by request rather than assumption:

| Domain              | Result                        |
| ------------------- | ----------------------------- |
| slateiq.com         | 200 — live                    |
| growthnation.ai     | 200 — live                    |
| noahmediagroup.com  | 200 — live (owner says sold)  |
| connect4.app        | 523 — origin unreachable      |
| wutzu.com           | parked on HugeDomains         |

Two wrinkles the request didn't anticipate:

1. **SlateIQ is not a company.** It's a project (`slug: "slate-iq"`) whose
   `company` is Noah Media Group — one of the dead ones. So slateiq.com can't
   attach to a company field. Owner's call: link companies normally, and let
   SlateIQ be an inline link inside the prose that already names it. The
   highlight on role id 4 reads "SlateIQ: film success prediction…", so the
   mention already exists — this links it, it doesn't invent copy.
2. **`highlights` renders nowhere.** Declared on `WorkExperience`, populated for
   6 roles, never read by any component. An inline link inside a highlight would
   be invisible, so highlights have to be surfaced for the plan to mean anything.
   Owner chose to render them.

## Plan

**Model absence explicitly.** Rather than an optional `url?`, `CompanySite` is a
required union of a URL or a stated reason there isn't one, keyed by company in a
`Record<CompanyName, CompanySite>`. Two consequences the owner asked for: a
missing link is a decision on record, not an oversight; and adding a company
without deciding its site is a **compile error**, because `Record` is exhaustive.

```ts
type CompanySite = `https://${string}` | "url-no-longer-active" | "no-public-url";
```

`no-public-url` is a second sentinel for Self-employed / Self-initiated (iOS):
they never had a site, so "no longer active" would be a lie.

**Where links render.** Experience list and case-study meta card. **Not** the
project card — it wraps its whole body in a `<Link>` to the case study, so a
company `<a>` inside would nest anchors: invalid HTML, React warns, browsers
mangle it.

**Inline links.** A markdown-lite `[text](url)` renderer for highlights. The
pattern only matches `https://`, so `[x](javascript:alert(1))` can't produce an
anchor — it falls through as literal text. No `dangerouslySetInnerHTML`.

Noah Media Group started as `url-no-longer-active` on the owner's "the rest is
dead" instruction, then flipped to the live URL once they confirmed it — the
domain had resolved all along, which is why it was raised rather than filled in
silently. `www` is stored because the bare domain 301s to it.

## Notes

- Project card deliberately excluded — see nested-anchor note above.
- `noUncheckedIndexedAccess` is on: regex match groups are `string | undefined`,
  so the parser has to narrow rather than destructure blindly.

## What changed after the plan

- **Scope grew to every prose field**, not just highlights, on the owner's call:
  `summary`, `hook`, and case-study paragraphs too. That surfaced two places a
  link *can't* render and the markup must degrade to its label via `plainText()`
  — `ProjectCard` (hook sits inside the card's `<Link>`) and `generateMetadata`
  (hook feeds `og:description`, which is plain text). The second would have
  leaked `[SlateIQ](https://…)` to every social scraper, and you'd only have
  found out from a bad LinkedIn preview.
- **Code review (high effort) found 7, all fixed** in `293bdee`. The two real
  ones were self-inflicted: truncated React keys traded away a uniqueness
  guarantee for a payload saving that wasn't real, and the new `<ul>` lost list
  semantics because Tailwind preflight sets `list-style:none` and WebKit drops
  the implicit role. jsdom derives roles from tags, so the test passed anyway —
  hence the explicit attribute assertion.
- **`ExternalLink` ended up styling-free**, which let `site-nav` and
  `site-footer` adopt it. They'd been hand-rolling `rel="noreferrer noopener"`
  (reversed tokens), so the drift the component claimed to prevent already
  existed. All five outbound links now share one `rel`.
- **Known conflict:** this branch is cut from `main`, but `random-bugs` also
  renders highlights and has its own tightened copy. `data/portfolio.ts` will
  conflict; `random-bugs`' rendering and copy should win. What's worth taking
  from here: `companySites`/`companyHref`, `ExternalLink`/`CompanyLink`,
  `LinkedText`/`plainText`, and the SlateIQ link in the data.
